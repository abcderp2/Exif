# Exif除去

画像を端末のブラウザ内だけで再生成し、Exif、GPS、撮影日時、機種名、作者情報、コメントなどの個人情報につながるメタデータを引き継がないための静的サイトです。

公開サイト

https://abcderp2.github.io/Exif/

## できること

ブラウザ標準の画像デコードと Canvas の再エンコードを使います。画像ファイルをサーバーへ送る処理、アクセス解析、広告、外部ライブラリの読み込みはありません。

対応の目安は次のとおりです。

| 入力 | 出力 | 注意点 |
| --- | --- | --- |
| JPEG | JPEG | 再エンコードするため画質設定の影響を受けます |
| PNG | PNG | 再エンコードするため色設定やビット深度などが変わることがあります |
| WebP | WebP | アニメーションは先頭フレームのみです |
| GIF | PNG | 先頭フレームを静止画として保存します |
| BMP、TIFF、AVIF、HEIF、HEIC、JPEG XL、ICO | WebPまたはPNG | ブラウザが入力形式を読み込める場合に処理できます |
| SVG | PNG | 外部参照や動作を含むSVGは安全のため拒否します |

すべての画像形式を単一の無料ブラウザアプリで無条件に読み込めるわけではありません。HEIC、HEIF、JPEG XLなどは端末とブラウザの対応状況に左右されます。処理できない場合は、ファイルを送信する代わりにその場で理由を表示します。

## 使い方

1. 「ファイルを選ぶ」を押すか、画像を置きます。
2. 一覧を確認し、「処理を開始」を押します。
3. 完了した画像の「保存」を押します。
4. 失敗した画像だけ「もう一度処理」を押せます。
5. 最初からやり直すときは「やり直す」を押します。

複数画像は順番に一つずつ処理します。エントリースマートフォンやタブレットで同時に大きな Canvas を作らないためです。

## 個人情報の扱い

このサイトは入力画像を画素から新しく作り直します。そのため入力ファイルに含まれていた Exif、GPS、IPTC、XMP、コメントなどを出力へコピーしません。JPEG の JFIF や PNG の色設定など、画像表示に必要な標準ヘッダーが出力形式によって生成されることはあります。

処理前には JPEG、PNG、WebP、GIF、TIFF の標準的なメタデータ領域を端末内で確認します。処理後にも出力先頭の標準領域を確認し、個人情報に当たる領域が見つからない場合に画面へ表示します。これはファイル形式の仕様全体を証明する検査ではないため、重要な画像は保存後に端末の詳細情報でも確認してください。

## 端末性能への配慮

画像の圧縮サイズだけではメモリ使用量を判断できません。展開後の画素数も確認し、標準設定では端末のメモリ量と論理コア数から安全目安を決めます。大きな画像は必要に応じて縮小します。

元のサイズを優先する設定もありますが、端末の Canvas 上限を超える画像は処理できません。処理中にブラウザが終了した場合は、タブを閉じている他のアプリを減らし、安全設定で一枚ずつやり直してください。

JPEG と WebP は再エンコードのため、元と完全に同じ画質にはなりません。画質設定は高品質 98、標準 96、軽量 90 から選べます。PNG も Canvas で再エンコードするため、色設定やビット深度などが変わることがあります。

## セキュリティ設計

実装は次の前提で保守します。

外部 JavaScript、CDN、フォント、分析タグに依存しない

Content Security Policy を HTML に設定する。GitHub PagesのHTML内CSPでは、CSP仕様上meta要素で適用されない指示に依存しない

ファイル名と解析結果を innerHTML に入れず、DOM のテキストとして表示する

拡張子だけを信用せず、先頭バイトとブラウザのデコード結果を使う

ファイル容量、個数、合計容量、展開後の画素数に上限を置く

画像の Object URL を処理終了時とリセット時に解放する

SVG の script、外部参照、イベント属性、動く要素を拒否してから PNG 化する

入力画像を localStorage、Cookie、URL、ログへ保存しない

処理は一件ずつ行い、画面更新の間にブラウザへ制御を返す

これはオンラインサービスへ画像を送信する設計ではありません。通信を発生させないことを CSP の connect-src none と外部依存なしの構成で確認しやすくしています。公開先の GitHub Pages やブラウザ自体の安全性まで、このコードだけで保証するものではありません。

## ファイル構成

`index.html` は画面と CSP を持ちます。

`styles.css` は端末幅、キーボード操作、タップ領域、色のコントラストを担当します。

`app.js` はファイル検査、メタデータ領域の確認、一覧、再試行、保存を担当します。

`image-worker.js` は対応ブラウザで画像の再エンコードを別スレッドに分けます。未対応ブラウザではメインスレッドの安全な処理へ戻ります。

`exif_remover.py` は同じ考え方で使えるローカル用のコマンドライン版です。Web版と依存関係は共有しません。

## 開発者向け確認

ビルド工程を増やさず、GitHub Pages の静的配信だけで公開できる構成です。ローカル確認は次のコマンドで行えます。

```sh
node --check app.js
node --check image-worker.js
python3 -m py_compile exif_remover.py
python3 -m http.server 8000
```

その後、ブラウザで `http://127.0.0.1:8000/` を開きます。ローカルの `file:` URL では Worker や CSP の挙動が異なるため、簡易サーバーを使ってください。

## 無料運用の範囲

サイトは静的ファイルだけで構成され、処理を実行するサーバーや有料APIを持ちません。そのため、追加課金なしで保守できます。将来ライブラリを追加する場合は、外部送信、ライセンス、ファイルサイズ、脆弱性対応、低性能端末でのメモリ使用量を確認してから採用してください。
