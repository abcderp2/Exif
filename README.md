# 画像メタデータクリーナー

JPEG、PNG、WebPを端末のブラウザ内だけで相互変換し、入力画像に含まれていたExif、GPS、撮影日時、機種名、作者情報、コメントなどを出力へ引き継がないための静的Webアプリです。

公開サイト

https://abcderp2.github.io/Exif/

## 主な機能

入力はJPEG、PNG、WebPに対応します。出力は入力と同じ形式、JPEG、PNG、WebPから選べます。

画像はサーバーへ送信しません。ブラウザの画像デコーダーとCanvasだけで画素を読み直し、新しいファイルを作ります。広告、アクセス解析、Cookie、外部JavaScript、CDN、画像処理Web APIは使いません。

処理前にファイル本体の形式と一般的な付加情報領域を確認します。処理後にも同じ構造検査を行い、個人情報につながる領域や構造異常が見つかった出力は保存できない状態で破棄します。

## 変換の扱い

| 入力 | JPEG出力 | PNG出力 | WebP出力 |
| --- | --- | --- | --- |
| JPEG | 対応 | 対応 | 対応 |
| PNG | 対応。透明部分は白 | 対応 | 対応 |
| WebP | 対応。透明部分は白 | 対応 | 対応 |

JPEGとWebPは再圧縮されます。画質は96、92、84から選べます。PNGもCanvasで再生成するため、元の色設定、ビット深度、パレット構造などが変わる場合があります。

アニメーションWebPを読み込めるブラウザでも、出力は先頭フレームの静止画です。

## 分析する領域

一般的なJPEG、PNG、WebPのファイル構造をたどり、次のような領域の有無を確認します。

Exif、GPS、撮影日時、メーカーと機種、編集ソフト、機器やレンズの識別情報、作者と著作権、説明とコメント、埋め込みサムネイル、XMP、IPTC、ICCプロファイル、PNGテキスト、PNG更新日時、WebPアニメーション情報。

画面とJSONレポートには分類だけを出します。GPS座標やコメント本文などの生の値は表示しません。

この分析は一般的な構造を対象にした確認です。鑑定、改ざん検出、ファイル仕様全体の完全な証明ではありません。重要な用途では、保存後のファイルを別の信頼できる手段でも確認してください。

## 低性能端末への配慮

一度に処理する画像は一件だけです。圧縮後のファイル容量だけでなく、展開後の画素数と一辺の長さにも上限を置きます。

標準の安全設定では、端末のメモリ量と論理コア数から約8MP、12MP、20MPのいずれかを目安にします。大きな画像は縦横比を保ったまま縮小します。

元の大きさを優先する設定では、約32MPまたは一辺8192pxを超える画像を処理しません。ブラウザが終了する、画面が止まる、保存に失敗する場合は、他のタブやアプリを閉じ、安全設定で一枚ずつ処理してください。

ファイル選択は最大20個、合計96MB、1個32MBに制限しています。

## セキュリティ設計

外部通信を行うコードを置かず、Content Security Policyのconnect-srcをnoneにしています。

拡張子とMIMEタイプだけを信用せず、先頭バイトでJPEG、PNG、WebPを判定します。拡張子やブラウザの申告と一致しない場合は画面へ注意を出します。

ファイル名、解析結果、エラーメッセージをinnerHTMLへ入れません。表示はtextContentとDOM APIで組み立てます。

入力画像をlocalStorage、sessionStorage、IndexedDB、Cookie、URL、ログへ保存しません。作成したObject URLは再処理、削除、リセット、ページ終了時に解放します。

SVGやHTMLなど、動作する内容を持てる形式は受け付けません。対応範囲をJPEG、PNG、WebPへ限定し、攻撃面と保守範囲を小さくしています。

詳しい前提と報告方法はSECURITY.mdを参照してください。

## やり直し

処理前の画像は一覧から個別に外せます。処理後は出力形式や画質を変えて、その画像だけ待機中へ戻せます。

画面全体のやり直すボタンは、分析や変換の途中でも現在の処理を中止し、出力URLと一覧を破棄します。元画像は変更しません。

Gitの変更はPull Request単位でまとめ、mainへはsquash mergeします。問題が見つかった場合は、直前のマージコミットをrevertすることで一つの変更として戻せます。

## ファイル構成

index.htmlは画面、説明、免責事項、Content Security Policyを持ちます。

styles.cssはスマートフォン、タブレット、パソコン、ダークモード、キーボード操作、動きを減らす設定、高コントラスト表示を担当します。

metadata.jsは形式判定、JPEG、PNG、WebPの構造検査、安全なJSONレポートを担当します。

app.jsは一覧、設定、逐次処理、再試行、保存、処理後検証、メモリ解放を担当します。

image-worker.jsは対応ブラウザで再エンコードを別スレッドへ分けます。未対応ブラウザではメインスレッドの処理へ戻ります。

tests/metadata.test.cjsは形式判定とメタデータ分類の回帰テストです。

tests/browser-audit.mjsはChromiumを実際に起動し、公開サイトと変更中のローカルサイトを操作する監査です。三形式の入力と出力、処理後検査、JSON保存、再処理、リセット、低性能端末向け縮小、画面幅、外部通信、JavaScript例外を確認します。

.github/workflows/browser-audit.ymlはPull Request、mainへの反映、手動実行時に構文検査、単体テスト、ブラウザ監査を実行します。Playwrightは監査時だけ固定版を一時インストールし、公開サイトの実行時依存関係にはしません。

exif_remover.pyはPillowを使う別用途のローカルCLIです。Web版の実行には使いません。

## 保守方法

ビルド工程と実行時依存関係はありません。静的ファイルをそのままGitHub Pagesで配信します。通常の修正はHTML、CSS、JavaScriptの該当ファイルだけで完結します。

Node.js 20以降で次を実行します。

```sh
npm run verify
```

ローカル表示は次のコマンドで確認できます。

```sh
python3 -m http.server 8000
```

その後、http://127.0.0.1:8000/ を開きます。file形式のURLではWorkerとContent Security Policyの挙動が異なるため、簡易サーバーを使います。

ブラウザ監査を手元で再実行する場合は、別のターミナルでローカルサーバーを起動したうえで次を実行します。

```sh
npm install --no-save --no-package-lock @playwright/test@1.55.0
npx playwright install chromium
node tests/browser-audit.mjs
```

通常はPull Requestを作成するとGitHub Actionsが同じ監査を自動実行します。変更時の確認事項はCONTRIBUTING.mdにまとめています。

## 無料運用

Web版は静的ファイルだけで動き、画像処理サーバー、有料API、データベース、外部ストレージを持ちません。サイトの機能を維持するための追加課金を必要とする設計にはしていません。

ブラウザ監査はリポジトリの開発時だけ実行され、公開サイトを閲覧する利用者の端末へPlaywrightを配信しません。

外部ライブラリを実行時に追加すると、脆弱性対応、ライセンス確認、配信停止、ファイル容量、低性能端末の負荷が増えます。必要性が明確でない実行時依存関係は追加しない方針です。
