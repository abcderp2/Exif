# 画像メタデータクリーナー

JPEG、PNG、WebPを端末のブラウザ内だけで一括処理し、入力画像に含まれていたExif、GPS、撮影日時、機種名、作者情報、コメントなどを出力へ引き継がない静的Webアプリです。

公開サイト

https://abcderp2.github.io/Exif/

## 主な機能

複数のJPEG、PNG、WebPをまとめて追加し、一件ずつ順番に処理します。出力は入力と同じ形式、JPEG、PNG、WebPから選べます。

画像はサーバーへ送信しません。ブラウザの画像デコーダーとCanvasだけで画素を読み直し、新しいファイルを作ります。広告、アクセス解析、Cookie、外部JavaScript、CDN、画像処理Web API、有料APIは使いません。

処理前にファイル本体の形式と一般的な付加情報領域を確認します。Exifを検知したかどうかを画面と安全なレポートへ記録し、処理後にも同じ構造検査を行います。Exif、個人情報につながる領域、構造異常が見つかった出力は保存できない状態で破棄します。

保存ファイル名は、元の名前に-cleanを付ける、元の名前を維持する、匿名化して連番にする、の3つから選べます。元の名前を維持する場合も、パス区切りや制御文字などは安全な文字へ置き換えます。匿名化を選ぶと、画像と分析レポートの名前に元のファイル名を記録しません。

分析結果は画像ごとのJSON、一覧のJSON、一覧のCSVとして保存できます。レポートには領域の分類だけを記録し、GPS座標、コメント本文、作者名などの生の値は出力しません。CSVは、ファイル名が表計算ソフトの数式として実行されないように無害化します。

## 一括処理の考え方

一度に最大20個まで追加できます。ただし、すべてを同時に展開しません。形式確認、構造分析、再エンコード、処理後検査を一件ずつ進めます。

完了した画像は個別に保存でき、完了分を順番に保存する操作もあります。ブラウザやOSによっては、複数ファイルの保存許可が必要です。ZIP生成はメモリ消費と保守依存を増やすため採用していません。

ファイル選択は最大20個、1個32MBです。合計上限は端末の性能目安に応じて48MB、64MB、96MBのいずれかになります。完了画像をブラウザ内に保持する量にも端末別の上限があります。上限に達した場合は、完了画像を保存して一覧から外してから残りを処理します。

## 変換の扱い

| 入力 | JPEG出力 | PNG出力 | WebP出力 |
| --- | --- | --- | --- |
| JPEG | 対応 | 対応 | 対応するブラウザのみ |
| PNG | 対応。透明部分は白 | 対応 | 対応するブラウザのみ |
| WebP | 対応。透明部分は白 | 対応 | 対応するブラウザのみ |

JPEGとWebPは再圧縮されます。画質は96、92、84から選べます。PNGもCanvasで再生成するため、元の色設定、ビット深度、パレット構造などが変わる場合があります。

アニメーションWebPを読み込めるブラウザでも、出力は先頭フレームの静止画です。

## 分析する領域

一般的なJPEG、PNG、WebPのファイル構造をたどり、Exif、GPS、撮影日時、メーカーと機種、編集ソフト、機器やレンズの識別情報、作者と著作権、説明とコメント、埋め込みサムネイル、XMP、IPTC、ICCプロファイル、PNGテキスト、PNG更新日時、WebPアニメーション情報などの領域を確認します。

画面、JSON、CSVには分類だけを出します。GPS座標やコメント本文などの生の値は表示しません。JSONとCSVにはExif検知と処理後のExif除去確認を含めます。

この分析は一般的な構造を対象にした確認です。鑑定、改ざん検出、ファイル仕様全体の完全な証明ではありません。重要な用途では、保存後のファイルを別の信頼できる手段でも確認してください。

## 低性能端末への配慮

標準の安全設定では、端末のメモリ量、論理コア数、タッチ端末かどうかを参考に、展開後の目安を約4MP、6MP、8MP、12MP、20MPから選びます。大きな画像は縦横比を保ったまま縮小します。

元の大きさを優先する設定では、約32MPまたは一辺8192pxを超える画像を処理しません。

対応ブラウザではOffscreenCanvasとWorkerへ再エンコードを分けます。Workerが使えない場合はメインスレッドへ戻ります。Worker処理が45秒を超えた場合は、端末が長時間固まる可能性を下げるため中止します。

メインスレッドで使ったCanvasは処理後に縮小し、Object URLは再処理、削除、リセット、ページ終了時に解放します。

## 画面と入力操作

画面は280px以上の幅で横にはみ出しにくい構成です。スマートフォン、タブレット、パソコン、縦向き、横向き、画面の切り欠き、タッチ操作、キーボード操作、ダークモード、動きを減らす設定、高コントラスト表示を考慮しています。

画像をブラウザ画面へドラッグしている間は、画面全体を画像の追加先として表示します。画面の別の場所へドロップしても、ブラウザが画像ファイルへ移動しないように抑止し、そのまま一覧へ追加します。フォルダーと画像以外の項目は受け付けません。

古いブラウザやOSを含む、すべての端末で同じ動作を保証するものではありません。WebP保存、Worker、複数ダウンロードなどはブラウザの機能に依存します。利用できない出力形式は画面上で選択できない状態になります。

## 検索とAIクローラー

HTMLでは検索エンジンによるインデックスとリンク追跡を許可しています。robots.txtには、一般クローラー、OAI-SearchBot、GPTBot、Claude-User、Claude-SearchBot、ClaudeBot、Google-Extendedへの許可を明記しています。AI向けの範囲と制限は[ai.txt](ai.txt)、正規URLは[sitemap.xml](sitemap.xml)にまとめています。

このリポジトリはGitHub Pagesのプロジェクトサイトとして公開されるため、robots.txtの公開先は https://abcderp2.github.io/Exif/robots.txt です。robots.txtの標準上、ドメイン全体へ適用される正式な配置先は https://abcderp2.github.io/robots.txt です。将来、ユーザーサイト用リポジトリまたは独自ドメインを用意する場合は、同じ内容をドメイン直下へ配置してください。

クローラー設定は公開中の静的ページに対する方針です。画像処理時に利用者が選んだ画像をクローラーや外部サービスへ送信する機能はありません。

## セキュリティ設計

外部通信を行うコードを置かず、Content Security Policyのconnect-srcをnoneにしています。スクリプト、スタイル、Workerは同一サイトの静的ファイルだけを許可し、オブジェクト、フレーム、フォーム送信、メディア読込を禁止しています。

拡張子とMIMEタイプだけを信用せず、先頭バイトでJPEG、PNG、WebPを判定します。拡張子やブラウザの申告と一致しない場合は画面へ注意を出します。

ファイル名、解析結果、エラーメッセージをinnerHTMLへ入れません。表示はtextContentとDOM APIで組み立てます。

入力画像をlocalStorage、sessionStorage、IndexedDB、Cookie、URL、ログへ保存しません。

SVGやHTMLなど、動作する内容を持てる形式は受け付けません。対応範囲をJPEG、PNG、WebPへ限定し、攻撃面と保守範囲を小さくしています。

詳しい前提と報告方法はSECURITY.mdを参照してください。

## やり直し

処理前と処理後の画像は一覧から個別に外せます。処理後は出力形式や画質を変えて、その画像だけ待機中へ戻せます。

画面全体のやり直すボタンは、分析や変換の途中でも現在の処理を中止し、出力URLと一覧を破棄します。元画像は変更しません。

Gitの変更はPull Request単位でまとめ、mainへはsquash mergeします。問題が見つかった場合は、直前のマージコミットをrevertすることで一つの変更として戻せます。

## ファイル構成

index.htmlは画面、説明、免責事項、検索公開設定、Content Security Policyを持ちます。

robots.txtは一般検索と主要AIクローラーへの公開方針を記載します。ai.txtはAI向けの範囲と制限、sitemap.xmlは正規URLを記載します。

styles.cssはスマートフォン、タブレット、パソコン、狭い画面、横向き、ダークモード、キーボード操作、動きを減らす設定、高コントラスト表示を担当します。

metadata.jsは形式判定、JPEG、PNG、WebPの構造検査、安全な分析オブジェクトを担当します。

reports.jsは一括JSONとCSVの生成、CSV数式注入対策を担当します。画像処理とは独立した純粋な処理にして、変更箇所を追いやすい構成にしています。

app.jsは一覧、設定、ファイル名の維持と匿名化、ドラッグ操作、逐次処理、再試行、保存、処理後検証、メモリ解放を担当します。

image-worker.jsは対応ブラウザで再エンコードを別スレッドへ分けます。未対応ブラウザではメインスレッドの処理へ戻ります。

tests/metadata.test.cjsは形式判定とメタデータ分類の回帰テストです。

tests/reports.test.cjsは一括JSON、CSV、表計算ソフト向けの数式注入対策を確認します。

tests/browser-audit.mjsはChromiumを実際に起動し、三形式の入力と出力、処理後検査、一括レポート、ドラッグ追加、再処理、リセット、低性能端末向け縮小、画面幅、外部通信、JavaScript例外を確認します。

tests/release-audit.mjsは有効なJPEGへExifとGPS領域を付けた入力を使い、画面での検出、再エンコード、保存後の再解析、JSONとCSV、順次保存、ドラッグ操作、robots.txt、不要なページ内リンクがないことを確認します。

.github/workflows/browser-audit.ymlはPull Request、mainへの反映、手動実行時に構文検査、単体テスト、ブラウザ監査を実行します。main反映時はGitHub Pagesへ今回の版が配信されるまで待ち、公開URLでもrelease-auditを実行します。Playwrightは監査時だけ固定版を一時インストールし、公開サイトの実行時依存関係にはしません。

exif_remover.pyはPillowを使う別用途のローカルCLIです。Web版の実行には使いません。

## 保守方法

ビルド工程と実行時依存関係はありません。静的ファイルをそのままGitHub Pagesで配信します。通常の修正はHTML、CSS、JavaScriptの該当ファイルだけで完結します。

Node.js 20以降で次を実行します。

```sh
npm run verify
```

ローカル表示は次のコマンドで確認できます。

```sh
python3 -m http.server 8000
```

その後、http://127.0.0.1:8000/ を開きます。file形式のURLではWorkerとContent Security Policyの挙動が異なるため、簡易サーバーを使います。

ブラウザ監査を手元で再実行する場合は、別のターミナルでローカルサーバーを起動したうえで次を実行します。

```sh
npm install --no-save --no-package-lock @playwright/test@1.55.0
npx playwright install chromium
node tests/browser-audit.mjs
AUDIT_RELEASE_TARGET=http://127.0.0.1:8000/ node tests/release-audit.mjs
```

通常はPull Requestを作成するとGitHub Actionsが同じ監査を自動実行します。変更時の確認事項はCONTRIBUTING.mdにまとめています。

## 無料運用

Web版は静的ファイルだけで動き、画像処理サーバー、有料API、データベース、外部ストレージを持ちません。サイトの機能を維持するための追加課金を必要とする設計にはしていません。

ブラウザ監査はリポジトリの開発時だけ実行され、公開サイトを閲覧する利用者の端末へPlaywrightを配信しません。

外部ライブラリを実行時に追加すると、脆弱性対応、ライセンス確認、配信停止、ファイル容量、低性能端末の負荷が増えます。必要性が明確でない実行時依存関係は追加しない方針です。
